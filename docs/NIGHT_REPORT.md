## Исправление настроек

Раньше парсер менял отдельную глобальную `g_pcopy_cfg`, а сохранение игрового меню не записывало
`present_copy` в INI. Удаление ключа не восстанавливало AUTO в текущем процессе. После сохранения
OFF мог продолжать действовать до выхода, а при новом запуске исчезать.

Теперь `present_copy` входит в `fg_config_t`, получает AUTO из defaults, наследуется из общего INI,
переопределяется профилем и записывается при сохранении. Сброс видимых настроек игрового меню
сохраняет эту скрытую настройку. Новых строк в меню нет. Приложение не менялось.

На ПК выполнен настоящий C-парсер из `main.c` с файловым вводом из памяти:
проверены сброс удалённого ключа, наследование, переопределение и границы значений.
Сохранение профиля и взаимодействие со старым приложением ещё нужно проверить на консоли.

## Эксперименты и гипотезы

Дополнительные хуки устанавливаются только в тестовых вариантах и только для CUSA05571/CUSA08809.
Они наблюдают `GetFlipStatus`, подписку `AddFlipEvent`, создание пакетов `InsertWaitFlipDone`.
Собственные запросы монитора и генератора пакетов обходят счётчики через исходные функции.
Счётчики могут включать вызовы библиотек игры. Подписка на событие сама по себе не доказывает ожидание на нём;
отсутствие этих вызовов не исключает прямой опрос GPU-меток.

| Test | Назначение | Что проверяет |
|---|---|---|
| 0 | обычное предъявление + исправление профиля | базовое поведение без новых диагностических хуков |
| 1 | то же предъявление, добавлена диагностика | какие API используются и сколько CPU-времени теряется |
| 2 | mid получает исходный flipArg, реальная копия — flipArg с инвертированным старшим битом | зависит ли ожидание от одинакового аргумента двух показов |
| 3 | отдельный FAST-подобный путь с 1/2 промежуточными кадрами и present copy | можно ли заполнить свободное обновление при 25–29 реальных fps |

Test 2 сохраняет порядок mid → real, GPU-ожидания и прежний pacer. Не подменяет статусы/счётчики,
не меняет метки игры. В CUSA05571 исходный аргумент равен 0; если игра ждёт именно индекс/метку,
одного отличающегося аргумента может оказаться недостаточно. Инверсия даёт отличие от аргумента
**той же пары**, но не резервирует отдельное пространство аргументов игры.

Test 3 использует существующие расчёт фаз и ограничение очереди, не включает отвергнутый timer pacer.
Предыдущий путь принудительно сбрасывал второй mid при present copy. Эксперимент позволяет его,
выбирая оба mid строго из собственного кольца `k` (не из `g_nmid`, описывающего первую аллокацию).
Курсор продвигается на фактическое количество промежуточных кадров; буферы копий остаются в другой половине.
Готовые GPU-fence не удалялись. Дополнительный warp/post увеличивает GPU-стоимость.

Test 3 — альтернативный режим для медленной игры, **не доказательство исправления 30→60**.
При двух mid соотношение промежуточных и реальных кадров отличается от QUALITY.
Стабильные 60 выходных обновлений зависят от CPU/GPU и поведения очереди; на ПК это не проверено.
